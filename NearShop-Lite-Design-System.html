🔍 Audit Report — v1.0 → v1.1

对照 shadcn/ui 设计规范的完整审查结果，已在 v1.1 中全部修复。

🔴 严重问题（Broken Logic）
严重 · 已修复
Danger Button 颜色与 Primary 完全一致
.cta-btn.danger { background: #1C1C1E } 与 Primary 按钮视觉无区分，"Cancel Payment"和"Confirm"看起来一模一样。

✅ 修复：改为 background: var(--color-destructive)（红色 #EF4444）。
严重 · 已修复
Status 颜色跨组件不一致
Order Card 的 Completed 用 #22C55E，Status Badge 的 COMPLETED 用 #16A34A（不同绿）。Canceled/Awaiting 同样存在类似偏差。

✅ 修复：所有状态统一使用 CSS 变量，两处引用同一 token。
严重 · 已修复
Countdown 正常状态就显示红色
倒计时"Normal"状态 border: 1.5px solid var(--color-error)，导致正常和紧急状态视觉一样，紧急状态失去意义。

✅ 修复：正常状态改为 --color-accent（amber），<5分钟才切换为 --color-destructive（红色）。
🟠 Token 问题（缺失 / 硬编码 / 未使用）
Token · 已修复
--color-primary 与 --color-text-primary 值相同
两个变量都是 #1C1C1E，语义重叠。shadcn 将品牌色（--primary）和文字色（--foreground）分开，防止品牌色改变时文字随之改变。

✅ 修复：拆分为 --color-primary（品牌动作色）+ --color-foreground（文字色）。
Token · 已修复
--color-amber 与 --color-warning 语义模糊
两者都是"橙色警告"但使用场景不同，无明确区分规则。开发者容易混用。

✅ 修复：--color-accent（#E8960C）= 品牌高亮（低库存、菜单按钮、Pending）；--color-warning（#EA580C）= 流程警告（Awaiting Order）。语义明确。
Token · 已修复
缺少 Foreground 配对 Token
shadcn 每个背景色都有配对的 foreground，防止对比度问题。原设计只有颜色没有 foreground 配对。

✅ 修复：为 primary/accent/destructive/success/warning/info 均添加 *-foreground。
Token · 已修复
缺少 --color-muted, --color-input, --color-ring
shadcn 核心 Token：muted（淡化背景）、input（表单背景）、ring（焦点环）。原设计统统用硬编码 #EFEFEF / #F3F4F6。

✅ 修复：新增三个 Token，替换所有硬编码值。
Token · 已修复
body 背景色与 --color-bg 不同
body { background: #FAFAFA } 但 Token 定义是 --color-bg: #F5F5F5，两种灰不一致。

✅ 修复：统一为 --color-background: #F5F5F5，body 使用变量。
Token · 已修复
Payment Method 颜色硬编码
QR紫色 #7C3AED、Cash绿色 #16A34A、Card深色 #1E293B 直接写在 class 里，不可全局管理。

✅ 修复：提取为 --color-pay-qr / cash / link / card。
未使用 · 已整理
--radius-xl / --color-primary-hover / --shadow-lg 定义但未使用
三个 Token 在原始 CSS 中没有任何地方引用，属于"幽灵 Token"，增加认知负担。

✅ 修复：--radius-xl 现用于 payment-icon（20px）；--color-primary-hover 用于 hover 状态；--shadow-lg 重命名为 --shadow-float 语义更清晰。
未使用 · 已整理
--text-3xl / --text-xl 从未在组件中使用
字体规格表里有 32px 和 20px，但没有任何 CSS class 使用这两个变量。

✅ 修复：在文档标题和新增章节标题中实际应用，保持规格的完整性。

已合并
.notif-dot + .order-dot — 两个相同功能的 class
.notif-dot（8px）和 .order-dot（10px）都是红色圆点，两套 CSS 维护两份。

✅ 修复：合并为单一 .dot 组件，用 .dot.sm 表示小尺寸。
已合并
.status-canceled 与 .status-refunded CSS 完全相同
两者 background 和 color 完全一致，视觉无区分。

✅ 修复：.status-refunded 添加 opacity: 0.7 进行区分，表示"已完结"状态比"取消"更淡化。
已合并
.block-title 与 .info-section-title 语义重叠
两个 class 都是卡片内部 15px 加粗标题，无差异，但分散在不同地方定义。

✅ 修复：统一为 .card-inner-title。

table-wrapper 缺少 . 前缀（无效 CSS）
原代码 table-wrapper { overflow-x: auto } 实为自定义元素选择器，不是 class 选择器，永远不会生效。

Token 使用规则（防止混淆）
--color-accent（品牌高亮）
✓ 低库存文字（5 in stock）
✓ 分类菜单按钮背景
✓ Pending Payment 状态
✓ 倒计时正常状态边框
--color-warning（流程警告）
✓ Awaiting Order 状态
✓ Link 支付方式背景
✗ 不用于品牌元素
✗ 不用于库存显示
--color-destructive（危险/错误）
✓ 0 in stock 文字
✓ Cancel Payment 按钮
✓ 通知红点
✓ 倒计时紧急状态（<5min）
--color-primary vs --color-foreground
Primary = 品牌动作色（按钮、选中态）
Foreground = 正文文字颜色
当前值相同，品牌扩展时可分开修改
